# What is ready in Go

A running tally of what has been ported from the Node/Mongo app into this service. Generated by
hand alongside the work, so treat it as a snapshot; `ROUTES.md` is the authoritative inventory of
the 209 routes the Node API declares.

**Hot-reload dev loop** (for development): `docker compose -f docker-compose.local.yml -f docker-compose.dev.yml up -d postgres`, then `air` (Go API on :5002, live-reload) and `cd web && GO_API_URL=http://localhost:5002 npm start -- --port 3005` (SPA with HMR). Open http://localhost:3005. See `.air.toml`.

**Verification levels used below**
- **Live** — exercised against real Postgres in the running all-in-one stack (`docker compose -f
  docker-compose.local.yml up`), request and response inspected.
- **Unit** — covered by Go tests, several with expected values captured from the real Node helpers.
- **Not Node-diffed** — nothing here has yet been diffed byte-for-byte against the live Node API
  with `scripts/parity.js` (that needs the Node+Mongo stack up), so every `ROUTES.md` box stays
  unchecked. "Ready" here means implemented + Live + Unit, not parity-certified.

domains whose reads are done (Client, Company, Bank, Sheet).

and **#27** (XLSX exports). Everything else in `docs/MIGRATION-AUDIT.md` (#1, #5, #6, #19–24, #26,
#28, #30, #32) is proven by a route above.
